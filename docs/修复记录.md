## 视觉复核：发黑、过亮、发白与固定墙块

后续根据用户截图再次校准，保留上表中的交互行为：

- 固定墙块与房间背景墙统一通过 `wallMaterial.ts` 创建材质：相同底色、格纹、粗糙度及非金属属性。固定块不额外叠乘深色，不再带独立浅蓝色调。正反面设置仅用于维持墙面剖视；不同朝向、阴影下仍有自然明暗。
- 加入本地生成的 PMREM 环境照明，给阴影面和非金属表面提供反射信息；环境强度从首次试调的 0.8 降为 0.35，避免泛白。上下文恢复时重新生成，销毁时释放。
- 曝光为 1，半球光 0.35，主光 1.8；降低出口发光和 Bloom，避免亮边过曝。灰色积木底色收低，普通描边为低强度灰蓝；选中依然为不透明青色，目标虚影和悬停发光保留。
- 可移动积木改为非金属涂漆表面，粗糙度 0.46；方向限制面在线性空间适度压暗，避免将半亮度 sRGB 当成半亮度光能。箭头使用受光照、接收阴影的材质，减少暗面箭头悬浮发白。
- 同光照下实际绘制固定块与墙面的材质并读取 GPU 像素，验证输出一致；默认和反向视角截图另行人工检查。该检查不要求不同朝向、不同遮挡的表面最终像素完全相同。

## 相机进入规则与边界停止

此前在 OrbitControls 的 change 事件中把进入房间的相机推到包围球外，导致连续放大时反复回退。该逻辑已移除。

- `data.ts` 的 `LEVEL_VIEW.allowInteriorView` 决定是否可进入内部；当前关卡按用户要求设为 `false`。这是关卡定义，不是玩家临时开关。
- 配置为 `false` 时，在临时相机上计算操作意图，沿旋转圆弧、缩放和平移的组合路径找到第一次碰撞，再把允许的运动提交到实际相机。不会先显示内部画面再退回，不会在旋转时擅自拉远半径。
- 边界停止后丢弃被挡的输入，反向缩放或反向旋转立即可用。预留近裁剪面余量；复位取景和改变窗口仍保留原语义。
- 路径检查使用曲率误差界细分，防止单次快速拖动的起点/终点均在外侧、但中间圆弧穿过房间。单元检查包括缩放到边界、连续受阻、反向释放、平移穿越、大幅旋转、合法圆弧及 300 组组合路径。

## 反面隐藏棱边

在房间 12 条外框棱边上叠加低对比度蓝灰虚线，线段沿实际关卡边界轻微外扩。使用正常深度测试，因此墙面或积木挡住的线段不显示，只在开口等空处可见；不改动墙面、出口与碰撞体。渲染回归检查其 12 条线段、虚线距离和深度规则。

## 验证与边界

- `npm test`：20 项通过，覆盖移动规则、当前通关路径、18,000 组随机对照、六面箭头方向、表面拓扑、手势、资源释放和相机边界路径。
- 视觉调整后的完整浏览器回归：三浏览器 40 项通过、2 项跳过，覆盖功能、相同光照下墙块像素一致与原有交互；Chromium 特有的 CDP 原生触控与 context-loss 注入在 Firefox/WebKit 明确跳过。
- 关卡相机配置调整后，定向执行三浏览器 12 项相机检查，全部通过：初始取景、resize/DPR 保留、真实滚轮进入房间，以及禁止进入时连续缩放/大幅旋转的边界停止和反向释放。
- `npm run build`：严格 TypeScript + 生产打包。Three.js 主包体积提示不影响构建正确性。
- `npm audit`：修复安装时发现的已有工具链依赖漏洞，Vite 更新到兼容的 8.3.6，当前审计无漏洞。
- WebGL 丢失时暂停输入/动画并显示恢复提示；恢复后重建渲染资源、重新生成阴影，保留棋局。实际注入测试已覆盖。
- 实体手机、不同品牌 GPU 和长时间热/功耗表现仍需要真实设备验收；自动化浏览器测试不能替代这些硬件测试，也不能证明所有未来新增关卡都无问题。

所有审计条目都已落实到实现或明确保留的设计规则；未声称不存在任何潜在新问题。新增回归测试用于防止已知反例再次出现。
